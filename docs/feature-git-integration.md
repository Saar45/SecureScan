# Feature F : Intégration Git automatisée et rapport PDF

Après qu'un scan a détecté des vulnérabilités et généré des remédiations, la plateforme peut automatiquement :

1. Créer une branche de correction dans le dépôt scanné
2. Y écrire des fichiers de documentation de remédiation (`.securescan/fix-*.md`)
3. Pousser la branche sur le remote (si `GIT_TOKEN` est configuré)
4. Générer un rapport de sécurité PDF complet

---

## Prérequis

Aucune action manuelle. `docker compose up --build` suffit :

- Les dépendances PHP (dont `dompdf/dompdf`) sont installées automatiquement par l'entrypoint du backend.
- Le schéma SQL inclut déjà la colonne `workdir` dans la table `scans`.
- Le répertoire `/tmp/reports` est créé automatiquement dans le conteneur.

Pour activer le **push vers le dépôt distant**, configurer `GIT_TOKEN` dans `.env` (voir section dédiée ci-dessous). Sans token, l'intégration Git fonctionne en local (branche + commit) mais ignore le push.

## `GitIntegrationService`

**Fichier :** `backend/src/Service/GitIntegrationService.php`

**Méthode principale :** `applyAndPush(Scan $scan, string $workdir, ?string $userToken = null): array`

Le troisième paramètre `$userToken` permet de passer le token OAuth de l'utilisateur connecté. S'il est absent ou vide, le service se rabat sur la variable d'environnement `GIT_TOKEN` (rétrocompatible avec les commandes CLI).

### Déroulement

1. **Collecte** toutes les remédiations avec `status = pending` et un `proposedFix` non vide.
2. **Résolution du token** via `getToken($userToken)` : token OAuth utilisateur → fallback sur `GIT_TOKEN` env.
3. **Détection des droits d'écriture** via `hasWriteAccess($owner, $repo, $token)` :
   - Si l'utilisateur a le droit `push` sur le dépôt → push direct.
   - Sinon → fork automatique du dépôt via `forkRepository()`, puis push vers le fork.
4. **Configure l'identité Git** : `SecureScan Bot <securescan-bot@securescan.local>`.
5. **Unshallow** le dépôt si nécessaire (le clone `--depth 1` du scan crée un shallow clone).
6. **Crée la branche** `fix/securescan-YYYY-MM-DD-{shortUuid}`.
7. **Écrit les fichiers de remédiation** dans `.securescan/` :
   - Un fichier Markdown par remédiation : `fix-{filename}-{id}.md`
   - Contenu : sévérité, outil source, fichier/ligne, catégorie OWASP, description, code brut, fix proposé.
8. **Commit** avec un message formaté :
   ```
   [SecureScan] Security remediations for scan {shortId}

   Automated security fix documentation generated by SecureScan.
   Scan score: XX/100
   Findings: N
   ```
9. **Push** vers le remote avec `-u origin {branch}` (ignoré si pas de token).
10. **Création de la Pull Request** via l'API GitHub :
    - Si push direct → PR classique sur le dépôt original.
    - Si fork → PR cross-repo (`head: forkOwner:branch` vers le dépôt original).
11. **Met à jour** chaque remédiation en base : `status = applied`, `gitBranchName = {branch}`, `prUrl`.
12. **Retourne** `['branch' => ..., 'prUrl' => ...]`.

### Méthodes internes

| Méthode | Rôle |
|---------|------|
| `getToken(?string $userToken)` | Résout le token : OAuth utilisateur → fallback `GIT_TOKEN` env |
| `hasWriteAccess($owner, $repo, $token)` | Vérifie les permissions `push` via l'API GitHub |
| `forkRepository($owner, $repo, $token)` | Fork le dépôt et attend qu'il soit prêt (polling 30s max) |
| `parseOwnerRepo($repoUrl)` | Extrait `[owner, repo]` depuis une URL GitHub |
| `collectPendingRemediations()` | Filtre les remédiations pending avec un proposedFix non vide |
| `injectTokenInRemoteUrl($workdir, $token)` | Réécrit l'URL HTTPS du remote avec le token |
| `configureGitIdentity()` | `git config user.name` + `user.email` |
| `unshallowIfNeeded()` | `git fetch --unshallow` si `.git/shallow` existe |
| `createBranch()` | `git checkout -b {branch}` |
| `writeRemediationFiles()` | Crée le dossier `.securescan/` et écrit les fichiers `.md` |
| `buildRemediationMarkdown()` | Formate un fichier Markdown pour un finding + sa remédiation |
| `commitChanges()` | `git add -A` + `git commit -m {message}` |
| `pushBranch($workdir, $branchName, $token)` | `git push -u origin {branch}` |
| `createPullRequest($repoUrl, $branchName, $scan, $token, $forkFullName)` | Crée la PR (classique ou cross-repo si fork) |

## `ReportGenerator`

**Fichier :** `backend/src/Service/ReportGenerator.php`

**Méthode principale :** `generatePdfReport(Scan $scan, string $outputDir): string`

### Déroulement

1. Agrège les findings par sévérité et par catégorie OWASP.
2. Rend le template Twig `templates/report/security_report.html.twig`.
3. Convertit le HTML en PDF via DomPDF (format A4 portrait, police Helvetica).
4. Écrit le fichier : `{outputDir}/securescan-report-{shortId}-{timestamp}.pdf`.
5. Retourne le chemin absolu du fichier.

### Contenu du rapport PDF

- **En-tête** : nom du projet, URL du dépôt, ID du scan, date, statut
- **Badge de score** coloré : vert (>= 70), orange (>= 40), rouge (< 40)
- **Cartes de sévérité** : compteurs CRITICAL / HIGH / MEDIUM / LOW / INFO
- **Findings par catégorie OWASP** : chaque finding avec indicateur de sévérité, localisation (fichier + ligne), description, bloc de code brut, encart de remédiation
- **Pied de page** : date de génération

### Template

**Fichier :** `backend/templates/report/security_report.html.twig`

Document HTML autonome avec CSS inline. DomPDF a besoin d'une page HTML complète, donc pas de `{% extends %}` — c'est un document standalone.

## Commandes CLI

### `app:git-integration`

Applique les remédiations Git et génère un rapport PDF pour un scan existant.

```bash
docker compose exec backend php bin/console app:git-integration <scan-id> [--report-dir=/tmp/reports]
```

| Argument / Option | Requis | Défaut          | Description                         |
|-------------------|--------|-----------------|-------------------------------------|
| `scan-id`         | oui    | —               | UUID du scan à traiter              |
| `--report-dir`    | non    | `/tmp/reports`  | Répertoire de sortie du rapport PDF |

**Comportement :**
1. Récupère le scan et vérifie que son `workdir` existe toujours sur disque.
2. Appelle `GitIntegrationService::applyAndPush()`.
3. Appelle `ReportGenerator::generatePdfReport()`.
4. Affiche un résumé : branche créée, statut du push, chemin du rapport.

### `app:full-pipeline`

Pipeline complet en une commande : scan + intégration Git + rapport PDF. Idéal pour les démos.

```bash
docker compose exec backend php bin/console app:full-pipeline <repo-url> [project-name] [--report-dir=/tmp/reports]
```

| Argument / Option | Requis | Défaut                    | Description                         |
|-------------------|--------|---------------------------|-------------------------------------|
| `repo-url`        | oui    | —                         | URL du dépôt Git à scanner          |
| `project-name`    | non    | `Project for {repo-url}`  | Nom du projet                       |
| `--report-dir`    | non    | `/tmp/reports`            | Répertoire de sortie du rapport PDF |

**Étapes :**
1. **Préparation** : recherche ou crée le projet en base.
2. **Scan** : exécute le pipeline complet via `ScanManager`.
3. **Intégration Git + Rapport** : crée la branche, commit, push (si token), génère le PDF.

## Authentification Git

### Via GitHub OAuth (recommandé — interface web)

Lorsqu'un utilisateur se connecte via GitHub OAuth sur l'interface web, son token OAuth est automatiquement utilisé pour les opérations Git (push, PR). Aucune configuration manuelle n'est nécessaire.

Voir `docs/feature-oauth.md` pour le détail de l'implémentation OAuth.

### Via `GIT_TOKEN` (fallback — CLI)

La variable `GIT_TOKEN` active le push authentifié pour les commandes CLI. Sans elle, tout fonctionne sauf le push (branche + commit restent locaux dans le conteneur).

1. Créer un **Personal Access Token** GitHub avec le scope `repo` :
   GitHub → Settings → Developer settings → Personal access tokens → Generate new token
2. Ajouter dans `.env` à la racine du projet :
   ```
   GIT_TOKEN=ghp_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
   ```
3. Relancer les conteneurs : `docker compose up --build`

Le token est passé au conteneur backend via `docker-compose.yml` (`GIT_TOKEN=${GIT_TOKEN}`) et lu à l'exécution par `GitIntegrationService` via `$_ENV['GIT_TOKEN']`.

### Logique de fork automatique

Lorsqu'un utilisateur lance "Apply Fixes & Create PR" depuis l'interface web :

1. Le service vérifie si l'utilisateur a le droit `push` sur le dépôt (via `GET /repos/{owner}/{repo}` → `permissions.push`).
2. **Si oui** (propre dépôt ou collaborateur) : push direct + PR classique.
3. **Si non** (dépôt tiers) : fork automatique → push vers le fork → PR cross-repo vers le dépôt original.

## Modifications apportées au schéma

### Colonne `workdir` sur `scans`

```sql
-- mysql/init/01-schema.sql
ALTER TABLE scans ADD COLUMN workdir VARCHAR(500) DEFAULT NULL;
```

Le `ScanManager` persiste le chemin du répertoire de travail (`/tmp/scans/{uuid}`) sur l'entité `Scan` juste après `prepareWorkdir()`. Cela permet à `GitIntegrationCommand` de retrouver le dépôt cloné sans paramètre supplémentaire.

**Entité Doctrine :** `backend/src/Entity/Scan.php` — propriété `$workdir` avec getter/setter.

## Exemple de bout en bout

```bash
# 1. Configurer le token GitHub (optionnel, nécessaire pour le push)
#    Éditer .env : GIT_TOKEN=ghp_...

# 2. Démarrer les services
docker compose up -d --build

# 3. Pipeline complet
docker compose exec backend php bin/console app:full-pipeline \
  https://github.com/OWASP/NodeGoat \
  "NodeGoat Security Audit"

# Sortie attendue :
#   === ETAPE 1/3 : Preparation du projet ===
#   Nouveau projet cree : a1b2c3d4-...
#
#   === ETAPE 2/3 : Scan de securite ===
#   Scan ID      : e5f6g7h8-...
#   Statut       : completed
#   Score global : 45.00
#   Findings     : 12
#
#   === ETAPE 3/3 : Integration Git et rapport ===
#   Branche creee : fix/securescan-2026-03-03-e5f6g7h8
#   Push effectue vers le depot distant.
#   Rapport PDF : /tmp/reports/securescan-report-e5f6g7h8-20260303-143022.pdf

# 4. Ou en deux étapes séparées :
docker compose exec backend php bin/console app:test-scan https://github.com/OWASP/NodeGoat
# → noter le Scan ID, puis :
docker compose exec backend php bin/console app:git-integration <scan-id>
```
